# 言葉手帖 · 日语纸笔听写

[English](README.md)

适合手机布局的日语听写小助手：听假名和例句，在纸上写，最后展开答案、手动标错。
每天自动选词，错词按间隔复习，不需要付费 API 密钥。

公开版附带 **20 个原创示例词和两种自然语音**，不含个人 MOJi 学习记录或线上账号配置。
示例用于体验流程，不是官方 JLPT 词表，也没有声称经过 N1 考试频率统计。

## 快速开始

安装 Node.js **22.13 或更新版本**和 Git：

```sh
git clone https://github.com/Chenqiang-Zhang/kotoba-dictation.git
cd kotoba-dictation
npm ci
npm run db:setup
npm run dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。本地入口会自动进入你的本地实例，
不需要登录 ChatGPT 或 MOJi。首次访问初始化示例词库；`db:setup` 可以重复执行。

这是**每个安装实例由一个人使用**的版本。本地服务只监听本机地址，本地登录仅用于开发。
词库在实例内共享，听写记录按身份保存；不同使用者应各自安装。
项目没有提供通用公网 Worker 的完整认证系统。

## 怎么听写

1. 开始今日练习，纸上作答；听写时隐藏答案。
2. 依次播放题号、假名、例句。可调声音、语速和落笔间隔，也可暂停或重播。
3. 展开答案，标错，可记录错写内容、错误类别和备注；确认其余正确后保存。
4. 在错词本和历史页查看记录。更正追加新记录，保留过去版本。

每天按日本时间生成最多 20 词，优先到期错词，再选未练习词。
导入数据若提供熟悉度和学习日期，也会用于排序；缺失的数据保持未知。
错词次日复习，之后答对依次安排 3、7、14、30 天。
当天保存的题目快照不会因为刷新、重启或后来导入词库而重新抽取。

## 导入自己的词库

进入「**词库与导入**」，选择替换或合并，然后选择 JSON 文件。
可以从 [完整示例](examples/words.example.json) 开始修改；
[JSON 格式说明](examples/words.schema.json) 列出了字段与限制。

```json
{
  "source": "我的词表",
  "words": [
    {
      "sourceId": "my-word-001",
      "word": "検討",
      "reading": "けんとう",
      "meaning": "考虑；研究",
      "example": "新しい方法を検討しています。",
      "exampleSource": "自己编写"
    }
  ]
}
```

编号要稳定且不能重复。分数、学习轮次、学习日期可不填，程序不会编造。
导入时间由服务端记录。替换会更新当前词库，合并按编号新增或更新；
已有听写快照、错词与评分历史保留，所以当天练习仍可能显示之前的词。
程序先验证完整文件，再写入数据库。

本版不登录或抓取 MOJi，也没有启用自动同步。请自行取得有权使用的词条并导入，
没有提供的例句不会自动补造。

## 语音

示例词库附带「四国めたん」「春日部つむぎ」两种 VOICEVOX 录音，播放前完整加载。
新导入词需要另行生成录音，也可以主动选择「**设备日语语音（备用）**」；
程序不会静默换声音。设备需安装日语语音，手机实际播放和发音质量需自行试听。

如需离线生成录音，请在独立 Python 环境安装官方 `voicevox-core` 0.17.0 wheel
和 `imageio-ffmpeg==0.6.0`，通过
[Core 发布页下载器](https://github.com/VOICEVOX/voicevox_core/releases)
准备对应 ONNX Runtime、Open JTalk 词典和 0.16.4 声音模型。
运行时和模型放在本项目目录之外，然后执行：

```sh
python scripts/generate-voices.py --runtime /path/to/voicevox/core
```

默认重建示例录音；`--input /path/to/words.json` 指定另一份词库，
`--keep-existing` 保留以前的录音映射，供历史快照继续使用。
修改声音清单后重启开发服务。自定义清单与录音会暴露对应文本，请仅保存在私人版本中；
公开检查只允许示例词句。语音的许可与署名见 [第三方说明](THIRD_PARTY_NOTICES.md)。

## 记录、备份与手机部署

本地词库、听写、评分和备注保存在 `.wrangler/state`，Git 会忽略这些文件。
界面可以导出 JSON 记录备份，但它不是数据库恢复入口。
需要完整备份时先停止服务，再私人备份整个 `.wrangler/state`；
恢复该目录后重新启动即可。个人导入文件放在被忽略的 `data/private/` 或项目目录之外。
声音和语速偏好保存在当前浏览器。

如需手机访问，可通过 Codex Sites 插件将代码部署到**自己的 owner-private 私人站点**：
新建站点和名为 `DB` 的 D1 绑定，将新项目 ID 写入部署副本的 `.openai/hosting.json`，
应用 `drizzle/` 迁移，并保留私人网关认证。部署副本与公开模板分开维护。
公开模板不附带任何线上项目 ID、凭据或个人数据库；本次没有验证复用版的新私人站点部署。

## 开发与检查

使用 React、Vinext/Vite 和 Cloudflare D1：

```sh
npm run check
```

依次检查公开文件、运行领域逻辑与音频测试、检查类型、构建。
GitHub Actions 会重复这些检查。`npm run verify:local` 创建独立的临时数据库，
自动启动和重启本地服务，验证认证、评分、导入与持久化，最后删除测试数据，
不会修改你的学习记录；它不能替代真实手机的试听验证。
